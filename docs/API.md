# API

Venn's JSON API is served under `/api` by both the Cloudflare Worker and the Node server. Writes must be sent as `application/json`. Times are UTC milliseconds.

## Privacy settings

Organizers can switch these on when creating a poll (`POST /api/events`) or later (`PUT /api/events/:id/settings`). The server enforces them, so hidden data never reaches other guests:

| Setting        | What it does                                                                                                                                                 |
| -------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `requireEmail` | Everyone who answers must send an `email`. Only the organizer sees it: each response has an `email` field for the organizer, and for the person who gave it. |
| `hideNames`    | Other guests see each response named `Guest 1`, `Guest 2`… The answers still show, so everyone can see which dates work.                                     |
| `hideResults`  | Other guests get only their own response, plus `responses`: how many people have answered. The picked date still shows once the organizer picks it.          |

One more on/off setting works the same way: `retro`, the poll's **Retro look**. Its page opens in the retrofuturist look for everyone (`public/retro-app.css`), and its emails come in neon too.

## Deadline and reminders

A poll with `requireEmail` can close at a deadline. Send `deadline` (UTC ms, at least an hour ahead and within 30 days) when creating the poll, or later with `PUT /api/events/:id/deadline`. Everyone sees `deadline` on the poll; from then until a date is picked, only the organizer can add or change answers (`403` for anyone else). Turning `requireEmail` off removes the deadline.

The organizer can also list `invitees` (up to 50 emails) and how often to remind them, `remindEvery`: `1`, `2` or `3` days, or `0` for only the day before. When the server sends email, those who haven't answered with that email get a reminder that often, and once more the day before, at most 5 in all; each has a one-click unsubscribe. At the deadline, the organizer (if they gave their email) gets one email with the best time so far. The invitees' emails are kept with the organizer's private settings and only the organizer sees them; they're deleted with the poll.

The reminders go out from an hourly run: a Cron Trigger on Cloudflare (`wrangler.toml`), and a timer in `server.js`.

## The next one of a plan

Book clubs, run clubs and game nights come round again. Once the date is picked, the organizer's "Plan the next one" opens `/new/pick?copy=<id>&next` (or `/new/free`): the poll copied, with dates that have passed dropped, or all moved on by whole weeks when none are left, at the same local times whatever daylight saving does. The code is in [`public/copy-poll.js`](../public/copy-poll.js). A plain copy (`?copy=<id>`, "Duplicate poll") does the same without `&next`.

| Field      | What it does                                                                                                                                         |
| ---------- | ---------------------------------------------------------------------------------------------------------------------------------------------------- |
| `seriesOf` | The id of the poll this one follows on from, sent by the app for `&next`. If that poll no longer exists it's left out. Kept when the poll is edited. |

Its organizer can then bring last time's group back from the new poll's page. Polls used to say how often they repeated (`repeat`), with an email to the organizer when it was time; that was taken out, and `repeat` is now ignored.

## Availability

`availability` maps each option's start time (UTC ms) to `2` (yes) or `1` (if needed). Anything missing means no.

```json
{ "name": "Ana", "availability": { "1793804400000": 2, "1793818800000": 1 } }
```

## The poll's picture

An organizer can give a poll any emoji (`emoji` when creating or changing it: one emoji, nothing else) or a picture of their own. The web app makes the picture in the browser: the middle square at 512 × 512, and a 1200 × 630 card with the poll's name for link previews, both JPEG. It uploads them with `PUT /api/events/:id/image` once the poll exists, and again when the poll is edited (so the card has the new name) or copied.

- `icon` is required, at most 200 KB; `card` is optional, at most 300 KB. Each must be a JPEG, PNG or WebP, which the server checks from its first bytes, not from what it says it is.
- `GET /api/events/:id` then includes `image: { v, card, type }`. `v` changes whenever the picture does.
- `icon.jpg` and `card.jpg` serve the picture as itself (`content-type` from its bytes, `x-content-type-options: nosniff`, and a `content-security-policy` of `default-src 'none'; sandbox`). With the current `?v=` they're cached for a year; without it, checked each time.
- With a card, the poll's link preview (`og:image`) is `card.jpg?v=…`; without one, Venn's own. The picked date's `event.ics` lists the icon as an RFC 7986 `IMAGE` (`DISPLAY=BADGE`).
- Deleting the poll deletes its picture.

## Brand templates

An organization's own template, so every poll its team sends shows its look. It's made at `/brand` in the web app ([`public/brand.js`](../public/brand.js), [`src/brands.js`](../src/brands.js)). While it's made, `/brand/preview` shows the real poll page with a sample poll in its look, in a frame; [`public/brand-demo.js`](../public/brand-demo.js) answers that page's requests in the browser, so nothing is saved.

| Field                    | What it does                                                                                                                                                                                                                                                                                                                                                                             |
| ------------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `name`                   | The organization's name, shown with its logo over its polls. Required, at most 60 characters.                                                                                                                                                                                                                                                                                            |
| `accent`                 | A colour, `#rrggbb`. The app nudges it until it reads at 4.5:1 on Venn's backgrounds in light and dark mode (`palette` in [`public/brand-look.js`](../public/brand-look.js)). Picks keep the key's green, amber and pink.                                                                                                                                                                |
| `bg`, `surface`, `text`  | The page's own background, cards and text, `#rrggbb`, the same in light and dark mode (`surface` and `text` only with `bg`). The app keeps text, muted text and the accent at 4.5:1 on all of them, and keeps cards on the background's side, light or dark (`scheme` in [`public/brand-look.js`](../public/brand-look.js)). Without `bg`, polls keep Venn's light and dark backgrounds. |
| `font`, `bodyFont`       | Headings and everything else: `sans`, `serif`, `rounded`, `mono`, `slab`, `humanist`, `condensed` or `elegant`, all system fonts, so nothing more is downloaded. Left out, Venn's own.                                                                                                                                                                                                   |
| `corners`                | `square`, `soft` (Venn's own) or `round`.                                                                                                                                                                                                                                                                                                                                                |
| `yes`, `maybe`, `no`     | The answers' own colours (available, if needed, unavailable), `#rrggbb`, each with ink made to read on it. Left out, Venn's green, amber and pink.                                                                                                                                                                                                                                       |
| `buttons`                | `pill` (Venn's own) or `corners`: buttons, pills and switches take the template's corners.                                                                                                                                                                                                                                                                                               |
| `logoSize`               | How tall the logo shows over its polls: `small` (40 px, the default), `medium` (64) or `large` (96).                                                                                                                                                                                                                                                                                     |
| `hideName`               | `true` leaves the name out next to the logo (when the logo already says it); the logo then carries the name for screen readers.                                                                                                                                                                                                                                                          |
| `title`, `note`, `where` | What a new poll from it starts with: its name, note for everyone and place.                                                                                                                                                                                                                                                                                                              |
| `emoji`                  | The poll's emoji, when the organizer doesn't choose one.                                                                                                                                                                                                                                                                                                                                 |

Where sign-in is set up ([Accounts](ACCOUNTS.md)), making a template needs a signed-in session (`POST /api/brands` answers 401 without one) and the template is kept with that account; without sign-in, no account is needed. Like a poll, a template has two links: the **share link**, `/new?brand=<id>`, for the team (anyone with it can make polls from it, but not change it), and the **manage link**, `/brand/<id>#admin=<adminToken>`, kept private. The app also keeps the token in the browser's local storage.

A poll made with `brand` returns `brand: { id, name, logo, … }` (the fields above that are set) from `GET /api/events/:id`, and its page shows that look (the retro look gives way to it). Editing the poll keeps its brand. Delete the template and its polls go back to Venn's look.

## Authentication

No account is needed. Two secrets, both returned once when they're created, prove who you are:

- **`adminToken`** (from `POST /api/events`): send it as `x-admin-token` for organizer-only calls.
- **`editToken`** (from `POST /api/events/:id/participants`): send it as `x-edit-token` to change or remove that response.

The server stores only SHA-256 hashes of these tokens. In the web app they live in the URL fragment and the browser's local storage.

### Accounts (optional)

When the server has sign-in set up ([Accounts](ACCOUNTS.md)), a signed-in browser carries a session cookie, and polls and templates kept with that account need no `x-admin-token`: organizer calls work with the session (from this site only). `GET /api/events/:id` and `GET /api/brands/:id` give the organizer's view only with `x-organizer: 1`.

| Method   | Path                                      | What it does                                                                                                                                                                         |
| -------- | ----------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `GET`    | `/api/auth/:provider?next=/me`            | Starts signing in (`google`, `microsoft` or `github`, as listed in `GET /api/config` → `accounts`). Comes back to `next` (a path on this site).                                      |
| `POST`   | `/api/auth/logout`                        | Signs out.                                                                                                                                                                           |
| `GET`    | `/api/me`                                 | `{ user: { name, email, provider, providerLabel }, polls: [{ id, title, emoji?, createdAt, finalStart, answers }], brands: [{ id, name, logoV }] }`, or `{ user: null, providers }`. |
| `POST`   | `/api/me/claim`                           | `{ polls: [{ id, token }], brands: [{ id, token }] }`: keep these with the account (each token is checked) → `{ added: { polls, brands } }`.                                         |
| `DELETE` | `/api/me/polls/:id`, `/api/me/brands/:id` | Takes it off the list; it stays, with its link.                                                                                                                                      |
| `DELETE` | `/api/me`                                 | Deletes the account. Its polls and templates stay.                                                                                                                                   |

## Errors

Errors come back as JSON with an HTTP status: `{ "error": "This poll does not exist or was deleted" }`. Validation problems are `400`, missing permissions `403`, and unknown polls `404`.
