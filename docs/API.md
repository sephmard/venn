# API

Venn's JSON API is served under `/api` by both the Cloudflare Worker and the Node server. Writes must be sent as `application/json`. Times are UTC milliseconds.

## Endpoints

| `POST`           | `/api/events`                        | Create a poll → `{ id, adminToken }`. Specific times: `{ mode: "options", options: [{ start, end }] }` (UTC ms; up to 14 days long). Whole days: `slotMinutes: 1440`, with `durationMinutes` a multiple of 1440 to look for several days in a row. Hours that differ by day: `windows: [{ date, start, end }]` (minutes after midnight in the poll's time zone), with `slotMinutes` (default 30) and `durationMinutes`. Parts of the day: `layout: "parts"`, each option a morning (9–12), afternoon (12–5) or evening (6–10). ## Privacy settings

Organizers can switch these on when creating a poll (`POST /api/events`) or later (`PUT /api/events/:id/settings`). The server enforces them, so hidden data never reaches other guests:

| Setting        | What it does                                                                                                                                                 |
| -------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `requireEmail` | Everyone who answers must send an `email`. Only the organizer sees it: each response has an `email` field for the organizer, and for the person who gave it. |
| `hideNames`    | Other guests see each response named `Guest 1`, `Guest 2`… The answers still show, so everyone can see which dates work.                                     |
| `hideResults`  | Other guests get only their own response, plus `responses`: how many people have answered. The picked date still shows once the organizer picks it.          |

## Plans that repeat

Book clubs, run clubs and game nights come round again. A poll can say how often:

| Field      | What it does                                                                                                                                                                                                                       |
| ---------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `repeat`   | `"weekly"`, `"biweekly"` (every 2 weeks) or `"monthly"`; leave it out, or send `""` or `null` to `PUT /api/events/:id/settings`, for a plan that doesn't repeat. Anything else is a `400`. Kept when the organizer edits the poll. |
| `seriesOf` | The id of the poll this one follows on from. If that poll no longer exists it's left out. Creating a poll with `seriesOf` means the last one needs no reminder (below). Kept when the poll is edited.                              |

Once the date of a poll with `repeat` has passed, its organizer gets one email, "Time to plan next month's…?", when the server sends email and they gave an address. See [Notifications](NOTIFICATIONS.md#plans-that-repeat).

In the app, the organizer's "Plan next month's" opens `/new/pick?copy=<id>&next=monthly` (or `/new/free`, and `weekly` or `biweekly`): the poll copied with its dates moved on, the same weekday of the month for monthly (the 2nd Tuesday stays the 2nd Tuesday, the last Friday the last), at the same local times whatever daylight saving does. A plain copy (`?copy=<id>`) drops dates that have passed, or moves them all on by whole weeks when none are left. The code is in [`public/repeat.js`](../public/repeat.js).

## Availability

`availability` maps each option's start time (UTC ms) to `2` (yes) or `1` (if needed). Anything missing means no.

```json
{ "name": "Ana", "availability": { "1793804400000": 2, "1793818800000": 1 } }
```

## Authentication

There are no accounts. Two secrets, both returned once when they're created, prove who you are:

- **`adminToken`** (from `POST /api/events`): send it as `x-admin-token` for organizer-only calls.
- **`editToken`** (from `POST /api/events/:id/participants`): send it as `x-edit-token` to change or remove that response.

The server stores only SHA-256 hashes of these tokens. In the web app they live in the URL fragment and the browser's local storage.

## Errors

Errors come back as JSON with an HTTP status: `{ "error": "This poll does not exist or was deleted" }`. Validation problems are `400`, missing permissions `403`, and unknown polls `404`.
